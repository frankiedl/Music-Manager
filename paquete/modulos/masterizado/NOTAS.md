# «masterizado» module — Mastering tab on each album

## What it does
«🎚 Masterización» tab (`albumTab`). Tracks = `GM.order(g)`; source of each one = `GM.finalPath(s)||GM.bestVersion(s)`,
except the «… (máster).wav» files generated by this very module (skipped so a master is not re-mastered). Measures LUFS (BS.1770, verified
against ffmpeg ebur128: matches within 0.1 LU), loudness normalization («each song» or «album/relative» mode), peak limiter with 0.3 dB of extra headroom,
trim, fades, silences, ID3v2.3 + RIFF INFO tags, cover art (`g.cover`, PNG/JPEG; other formats or >3.5 MB are converted to JPEG),
waveform, listening with/without normalization. Exports: (a) its own uncompressed ZIP (no libraries, no CDN), (b) «Guardar másters en la
biblioteca» (save masters to the library) → `POST guardar_master` → `<song>/master/NN - Title (máster).wav`, never overwriting («… (2)»), with confirmation.
Album status selector (Draft · Mixing · Mastering · Ready to distribute); emits `GM.emit('masterizado:estado',{album,estado})`.

## Data
`GM.state('masterizado')[g.key] = {estado,modo,lufs,techo,bits,dither,artista,anio,genero,idioma,portada,fuera:[ids],pistas:{[songId]:{name,artist,trimStart,trimEnd,fadeIn,fadeOut,padStart,padEnd,previewNorm,meta:[{key,value}]}}}`. Never audio.
Tracks added by hand (dragged WAVs) are NOT remembered after reloading.

## Decisions
- WAV: read natively (original sample rate/bit depth). Non-WAV (MP3, FLAC…): `decodeAudioData` to 44.1 kHz float; exported at the chosen bit depth at 44.1 kHz.
- Memory: audio is only in memory while in use (on-demand loading, released after measuring/exporting); waveform peaks are kept. The thread is yielded per track/channel.
- Names: ZIP `NN - Title.wav`; library `NN - Title (máster).wav`.
- Limiter on sample peak (not a real true-peak limiter).

## Effects (implemented, uses the `vst` module)
- «Efectos · antes del limitador» panel (collapsed). Edits the chain with `GM.mods.vst.montarCadena` (VST3 + built-ins, presets). Main chain + «own chain» per track. Saved in `ajustes.fx = {on, cadena, porPista:{trackId:chain}}`.
- **Where it acts**: «Aplicar efectos» processes each track on the server when LOADING it (`traerFx` → `GM.mods.vst.procesar`, 24-bit WAV; if it goes above 0 dB the server lowers the volume and it is restored on decoding with `bajado_db`). So LUFS measurement, gain, limiter, listening and export already work on the audio with effects. Originals are not touched.
- In-memory cache per track+chain (`FXCACHE` → job id on the server; if it is gone it is processed again). Only tracks whose chain changed are reprocessed. «Quitar efectos» goes back to the original audio.
- Without `vst` or without pedalboard: the panel explains it (with vst's install button) and mastering works the same, without effects.
- Limits: not real time (round trip to the server); the audio with effects is downloaded whole (24-bit) on every load.

## Mastering a single song
`songAction` «🎚 Masterizar» (song page and song menu): opens the same UI in a window with a fake 1-track group; settings in `GM.state('masterizado')['cancion:'+id]`; «Guardar máster» writes into its `master/` folder.

## Mixtapes
`mixtapeAction` «🎚 Masterizar» (mixtape page): same UI in a window, tracks = `mixtape.items` in their order (`it.p` if present, otherwise `GM.finalPath||GM.bestVersion`). ↑/↓ reorder and are reflected in `mixtape.items` (`GM.mixSave()`). Settings in `GM.state('masterizado')['mix:'+id]` (includes `mixMasters` = saved path per item and `origMix` = original `it.p`).
- «Guardar máster» writes into `MIXTAPES/_masters/<id>/NN - title.wav` (`POST guardar_master?mix=`), without overwriting; NEVER into the songs' `master/`.
- «Usar en este mixtape» sets `it.p` = those WAVs (keeping the previous `it.p` in `origMix`) and calls `GM.mixSave()`; «Volver a las versiones originales» restores it. If `it.p` points to a master from this module, it is not mastered again: the original is used.
- Tested: reorder, save 3 WAVs, use/revert, and that `/api/mix_convertir` converts an `it.p` from `_masters` to MP3 (no core changes). Not tested: automatic MP3 regeneration in the mixtape UI after «Usar» (`GM.mixSave()` + core queue), nor real audio.

## FX1…FX5 per track and live monitoring
- The main chain becomes **5 slots** (`S.fx.cadena`, max. 5, the same for the album/mixtape/song). Each track stores `S.fx.porPista[id] = {m:[1,1,0,1,1], off:0}` (mask of the 5 slots and «all off»); if it is all ones it is deleted. The old per-track «own chains» are discarded on opening. Everything inside `GM.state('masterizado')`.
- UI: on each track, **FX1…FXn** and **∅** buttons; on top, a global **Con efectos / Original** (with effects / bypass) switch (both also bypass the effects on export). Adding the first slot switches to «Con efectos».
- With the **engine** (`sounddevice` installed and slots defined): pressing ▶ plays through the agent's engine (browser silent, L/R meter in the bar), buttons/switch are heard instantly, and order/trims/fades/«Oír igualada» are sent to the engine. Without the engine: A/B by render (the current song is reprocessed ~700 ms after the change). Other tracks are invalidated (`fxRevisar`) and reprocessed on export/measurement, so the export always reflects the current masks.
- Export: as before (effects on the server per track with the chain filtered by its mask → gain → limiter in the browser). Same graph as the engine (see the `vst` NOTAS).
- Tested in the browser with null output: ▶ with engine (position advances 1.02 s/s, meter, browser silent), FX2 off → mask [1,0,1], ∅ → `apagado`, Original/With effects → `efectos` false/true, pause, closing the modal closes the engine; 3-track mixtape: buttons on each row, automatic move to the next track, «Oír con volumen igualado» sends `gain_db` to the engine.
- Not tested: exporting a whole album with different masks (same logic, verified piece by piece), third-party plugins, real sound.
- To test with the null output: `localStorage.gm_sink='nulo'` and reload.

## ⚠ Effects DISABLED (user's decision, they were not responsive)
`const FX_ACTIVO=false` at the top of `modulo.js`: the «Efectos» panel, FX1…FX5, «Con efectos/Original», the live engine and the meter are hidden/inert; export and listening only use normalization (target LUFS + limiter). The `vst` module has `"distribuir": false` and no longer shows in Settings. All the code is kept to resume it (set `FX_ACTIVO=true` and `distribuir:true`).

## Master tags (WAV)
Masters are encoded from the decoded audio, so they **carry no metadata or cover from the original**; only the manager's are written: title, artist, album artist, album (in a mixtape = mixtape name), track n/total, year, genre, language, composer (the artist by default; it can be changed in the track's «Etiquetas»), copyright «© year owner» (owner from Settings; in mixtapes, `GM.mixCopy`), comment/ISRC/publisher… (track-specific fields), **lyrics (USLT, `GM.lyrics`)** and cover (APIC). Verified with ffprobe. WAV limitation: RIFF INFO has no lyrics field, they only go into the ID3 chunk (read by ffmpeg/ffprobe, not by every player). MP3/FLAC with lyrics are produced by the mixtape ZIP and the core's `mix_convertir` (not touched here).
