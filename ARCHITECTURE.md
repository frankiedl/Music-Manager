# Architecture

Music Manager is a local web app: a small **Python standard-library HTTP server** plus a **single-file web UI**, extended by
**modules**. Everything runs on `127.0.0.1`; the user's music never leaves the computer. Code identifiers, folder names and JSON
keys are in Spanish (the project started as a personal Spanish tool); comments and developer docs are in English.

## Folders

| Folder | What it is |
|---|---|
| `paquete/` (public repo) | The generic, distributable manager, generated by `distribucion/empaquetar.py`. Contains `gestor/` and `modulos/`. |
| `gestor/` | Server and UI. `gestor.py` = HTTP server and REST API; `index.html` = the whole UI (HTML + CSS + JS in one file); `common.py` = shared paths/config; `build_data.py`, `build_medios.py` = library scanners; `mover_carpetas.py`, `deshacer.py` = journaled file moves and undo; `arte_map.py` = layout of the `ARTE/` artwork folder; `assets/` = UI images. |
| `modulos/` | Optional features, one folder per module (`ajustes` settings, `estado` status/reports, `importar` import wizard, `masterizado` mastering). |
| `modulos/_core/` | Module framework: `gm.js` (client registry, `GM` API), `i18n.js` (runtime translator), `idiomas/*.json` (dictionaries), `modulos_core.py` (server-side loader/router), `acceso.py` (token/CORS for the optional web mode), `mixtape_pkg.py` (mixtape ZIP/HTML builder). |
| `modulos/_plantilla/` | Template for a new module (not shipped). |
| `datos/` | Created at runtime next to the app: the user's state and generated data (never committed, never packaged). |
| `construir/` | `construir.py` builds the executable with PyInstaller; `app.py` is the executable's entry point. |
| `manual/` | `hacer_manual.py` generates the PDF manuals (ESP/ENG/DEUT/PORT) with reportlab; the text itself stays multilingual. |
| `.github/workflows/` | GitHub Actions: builds Windows / Mac Intel / Mac Apple Silicon zips. |

In the author's private working tree there are also: `distribucion/` (packaging: `empaquetar.py`, `preparar_repo.py`, `plantilla/` = the generic server, `i18n/` = translation tooling, `licencia/`), `scripts/` (one-off maintenance scripts for the personal library), `web/` (static build of the UI for the optional hosted "web app" mode) and `extension/` (an MV3 browser extension that bridges a hosted UI to the local agent). They are not part of the public repo.

## Data files (in `datos/`)

| File | Content |
|---|---|
| `data.json`, `letras.json`, `medios.json` | Generated by the scanners from the library folders (songs, versions, lyrics, artwork/video). Rebuilt on "Refresh". |
| `estado.json` | The user's own work: tags, stars, notes, sketches, mixtapes, album order, names, per-module state (`GM.state`). |
| `ajustes.json` | Preferences shared by modules (`ctx.guardar_ajustes`). |
| `agente.json` | Pairing token and authorized origins for the optional web mode (`acceso.py`). |
| `decisiones.csv` | Append-only log of user decisions (merges, lyrics assignments…). |
| `diario_movimientos.jsonl` | Journal of every file move; `deshacer.py` replays it backwards to undo. |
| `config.json` (next to `datos/`) | Library folder, artist name, copyright owner, port. |

The library itself follows a fixed layout: `unreleased/`, `prereleased/`, `published/Singles/`, `published/Álbumes/`, `ARTE/`,
and inside each song `letra.txt`, `versiones/`, `master/`, `stems/`… (these names are part of the format and are not translated).

## Request flow

1. The browser loads `index.html`, which loads `/mod/_core/i18n.js`, `/mod/_core/gm.js` and then each module's JS/CSS listed by `/api/modulos`.
2. `init()` fetches `/api/config` and `/api/data` (plus `/api/letras` and `/api/medios`; the user state comes inside `/api/data` and is saved with `POST /api/state`) and renders the current view.
3. UI actions call REST routes in `gestor.py` (`do_GET` / `do_POST`: `/api/state`, `/api/refrescar`, `/api/mixtape`, `/api/unir`, `/api/soltar`, …). Long jobs return a job id and are polled.
4. Module calls go to `/api/mod/<id>/<route>`; `modulos_core.Registro.despachar` routes them to the module's `servidor.py`.
5. Audio and images are served with HTTP Range support from inside the library only (`safe_media` / `inside_root`).

## Modules

A module is `modulos/<id>/` with:

- `modulo.json`: `{"id", "nombre", "descripcion", "js": [...], "css": [...], "py": "servidor.py", "distribuir": true}` (`distribuir: false` keeps it out of the package).
- `modulo.js`: calls `GM.register({id, nav, render, home, albumTab, songAction, mixtapeAction, init})`. It talks to its server with `GM.api(id, 'route', body)` / `GM.apiBlob(...)`, reads the library through `GM.songs`, `GM.groups()`, `GM.bestVersion()`…, and keeps state in `GM.state(id)`.
- `servidor.py` (optional): `ROUTES = {"GET estado": fn, "POST guardar": fn}` and optional `setup(ctx)`. Each route is `fn(req, ctx)`: `req.arg/json/body/send/file/guardar_en`, `ctx.root` (library), `ctx.datos` (module's own data folder), `ctx.cfg`, `ctx.songs()`, `ctx.ffmpeg()`, `ctx.safe_name()`. The server must be restarted after editing a `servidor.py`.

See `modulos/_plantilla/` and `modulos/LEEME_MODULOS.md` (private tree) for a complete example.

## Internationalization

The **source language is Spanish**: UI strings are written in Spanish directly in `index.html` and the modules. `i18n.js`
observes the DOM and replaces every text node / `placeholder` / `title` / `aria-label` that matches an entry in
`modulos/_core/idiomas/<en|de|pt>.json`: `exactas` (exact strings) and `patrones` (`"{a} canciones" → "{a} songs"`). Native
`alert/confirm/prompt` are translated too, and requests carry an `X-Lang` header so the server can translate texts it writes
into files (`modulos_core.traducir`). Language: `?lang=xx` > saved choice > browser language.

**Rule: every new UI string goes into the dictionary.** Tooling (in `distribucion/i18n/` of the private tree): `extraer.py`
extracts all strings, `lotes/*.txt` hold the translations (`id ||| en ||| de ||| pt`), `compilar.py` writes the dictionaries,
`comprobar_idiomas.py` lists anything untranslated (static check) and, with `--url`, runs `cobertura.mjs --profundo`, a headless
crawl that clicks through every view, tab and dialog of a scratch instance and reports visible Spanish text.

## Package and executable

- `empaquetar.py` copies the generic server (`plantilla/`) and the distributable modules, and turns the personal `index.html`
  into the generic one with checked string patches (each patch must match exactly, or the build stops). It refuses to package
  any personal data file.
- `preparar_repo.py` builds the public repo tree (package + `construir/` + `manual/` + workflow + docs) and scans it for personal data.
- `construir/construir.py` runs PyInstaller (folder mode) and zips the app with the PDF manuals; CI does this on three OSes.

## Key functions

| `gestor/gestor.py` | |
|---|---|
| `main()` / `setup()` | Load config (asks for the library the first time), scan if needed, load modules, start `Servidor` on the first free port from 8765. |
| `H.do_GET` / `H.do_POST` | REST API and static/media serving (Range); access control via `acceso.py`. |
| `run_script()` | Runs a helper script (`build_data.py`, …) isolated, also from inside the executable. |
| `folder_signature()` | Cheap change detection of the library folders (UI shows "changes detected"). |
| `classify_drop()` | Decides where a dropped file goes (version, stem, lyrics, artwork…). |
| `run_mixtape()` / `mix_convert()` | Mixtape export: MP3 conversion with ffmpeg + `mixtape_pkg.construir`. |
| `cambiar_biblioteca()` | Switches the library folder live. |

| `gestor/index.html` (main script block) | |
|---|---|
| `init()`, `reload()` | Startup and data reload from `/api/data`. |
| `go(view, arg)`, `back()`, `render()` | Navigation and view dispatch. |
| `renderHome()`, `renderGroupBase()` / `albTabs()`, `renderSong()`, `renderMixtape()` | The main views (home, album/group with module tabs, song page, mixtape). |
| `groups()`, `bestVersion()` | Library model: albums/singles/projects and the best audio version of a song. |
| `save()` | Debounced save of the user state to `/api/state`. |
| `play()` | Bottom player. |
| `modal()`, `ask()`, `toast()` | Dialogs and notices (exposed to modules as `GM.ui`). |
